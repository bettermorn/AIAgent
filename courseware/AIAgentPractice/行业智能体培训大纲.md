# 行业专业知识智能体开发培训大纲（2 天 · 12 学时）

> **培训主题**：用 CodeBuddy 等 AI 编程智能体，开发行业专业知识智能体
> **培训时长**：2 天，每天 6 学时，共 12 学时（1 学时按 60 分钟计，含课间微休）
> **学员对象**：行业业务骨干、数字化/IT 工程师、产品经理、AI 应用开发初学者（会基本 Python 或能阅读代码更佳）
> **培训形式**：理论精讲 + 案例拆解 + 现场演示 + 动手实操（理论约 40%，案例约 25%，实操约 35%）

---

## 一、培训目标

学完后，学员应能：

1. **讲清楚**：智能体的概念、基本结构、自主程度分类，以及"什么任务适合用智能体"。
2. **看得懂**：智能体的分层技术架构，以及 ReAct、Plan-and-Execute、Router、Supervisor、Human-in-the-Loop、RAG 等常见工作流模式。
3. **走得通**：按"需求定义 → 知识工程 → 工具与编排 → 记忆 → 护栏 → 测试 → 上线"的完整流程开发智能体。
4. **做得出**：掌握行业智能体的 5 项核心技术设计：**任务编排、工具调用、记忆、护栏、专业知识库（RAG + 知识图谱）**，并能用 CodeBuddy 搭出一个可运行的最小原型。
5. **能判断**：看懂两个完整案例（中医方证学习智能体、海上风电运维智能体）的取舍，并能迁移到自己的行业。

## 三、Day 1：概念、架构、流程与核心技术

### M1　智能体的概念、类型与适用性判断（1 学时）

**学习目标**：能用一句话定义智能体，能给一个业务场景选对智能体类型。

| 时间 | 内容 | 要点 |
|---|---|---|
| 15 min | 1.1 什么是智能体 | 以大语言模型为"大脑"，能感知、推理规划、调用工具、执行并根据反馈调整；与"一问一答"聊天机器人的区别：**自主性、工具使用、多步骤执行** |
| 10 min | 1.2 智能体的基本结构 | 用户输入、所需知识、可用工具、决策步骤、最终输出；五大模块：LLM、记忆、工具、规划、执行与反馈循环；以"出差助手"为例拆解 |
| 20 min | 1.3 按自主程度分类 | 被动响应型 → 辅助决策型（Copilot）→ 任务执行型 → 半自主型 → 全自主型；多智能体协作是一种**系统组织方式**，而非单独的自主等级 |
| 10 min | 1.4 任务是否适合用智能体 | 判断维度：是否需要理解意图、调用多工具、动态决策、多步骤、风险与容错、是否需人工审批；判断表：查制度（知识库问答即可）、做报告（适合）、自动审批财务（不适合完全自动化 → 规则引擎 + 智能体辅助 + 人工审批） |
| 5 min | 1.5 小结与课堂小测 | 给 5 个业务场景，现场判断类型 |

**课堂练习**：把学员自己行业的 3 个业务场景填入"类型—自主程度—风险边界"表。
**关键结论**：高风险、高责任场景采用"**智能体辅助 + 规则约束 + 人工确认**"；落地顺序建议"被动响应 → 辅助决策 → 任务执行 → 半自主"逐级演进。

### M2　智能体的工作流模式与技术架构（1 学时）

**学习目标**：能为场景选工作流模式，并画出分层技术架构。

| 时间 | 内容 | 要点 |
|---|---|---|
| 25 min | 2.1 十种常见工作流模式 | 基础"感知—思考—行动"循环；**ReAct**（Thought→Action→Observation）；**Plan-and-Execute**；**Router**（含置信度与人工兜底）；并行智能体；**Reflection**（生成—评审—修正）；**Supervisor** 多智能体协作；**Human-in-the-Loop**；**RAG 智能体**；工具调用与异常恢复。每种讲"适用场景 / 优点 / 缺点" |
| 10 min | 2.2 选型速查 | 步骤少→基础循环；路径不确定→ReAct（必加步数上限）；步骤多需展示计划→Plan-and-Execute；多业务入口→Router；不可逆操作→HITL；依赖专业文档→RAG；上线生产→叠加异常恢复与可观测性 |
| 15 min | 2.3 统一分层架构 | 五层：**交互层 → 编排层 → 工具调用层 → 模型与知识层（LLM / RAG / 知识图谱 / 预测与优化模型）→ 治理与安全层**（身份与权限、数据分级、工具白名单、审批、审计、提示注入防护、输出引用、版本与回滚） |
| 10 min | 2.4 框架与协议概览 | LangGraph（状态图、检查点、`interrupt()`）、LangChain / LlamaIndex（RAG 组件）、OpenAI Agents SDK、Google ADK、Microsoft Agent Framework；协议：**MCP**（智能体↔工具）、**A2A**（智能体↔智能体）。**注意**：AutoGen 已归档，不建议新项目使用；框架版本变化快，务必固定版本并读当前文档 |

**关键工程原则**（贯穿全程）：
- 把自由推理变成可控状态机：状态 → 节点 → 转移条件 → 工具权限 → 超时重试 → 审批节点 → 结果校验。
- **循环必须设边界**：最大步数、重试次数、工具调用次数、Token 与时间。
- 区分三类失败：规划失败（重新拆解）、执行失败（重试/替换/降级）、结果质量失败（Reflection）。
- 统一结构化输出（status / summary / evidence / warnings / next_action）。

### M3　智能体开发流程（1 学时）

**学习目标**：掌握完整开发流程，知道每一步的交付物与常见坑。

| 时间 | 内容 | 要点 |
|---|---|---|
| 30 min | 3.1 通用八步法 | ① 明确任务与边界 ② 选择大语言模型 ③ 设计工具 ④ 设计记忆机制 ⑤ 搭建规划与推理逻辑 ⑥ 搭建执行与反馈循环 ⑦ 加入安全与限制机制 ⑧ 测试与迭代 |
| 15 min | 3.2 行业智能体的扩展流程 | 在八步法前后补充行业必需环节：**设计内容五要素**（用户对象 / 业务任务 / 输入信息 / 输出结果 / 成功标准 / 风险边界）→ **知识工程**（数据来源梳理、解析、校正、切块、入库、专家审校）→ 工程实现 → **评测基线** → 灰度上线 → **持续改进闭环**（反馈 → 根因分析 → 校准 → 黄金集门禁 → 灰度/全量） |
| 10 min | 3.3 用 CodeBuddy 开发的工作方式 | 先写"需求与设计文档"，再让 CodeBuddy 分模块生成；提示词写法（角色 + 约束 + 验收标准）；小步迭代、每步可运行；让 CodeBuddy 同时生成测试；人工审查关键代码（护栏、权限、数据写入） |
| 5 min | 3.4 小结 | 初学者策略：先做一到两个工具的最小可用版本，跑通闭环，再逐步加记忆、知识库与护栏 |

**对照阅读**：TCMRxAgent 与 WindOnMAgent 都是先有设计方案/需求文档，再落地实现；WindOnMAgent 的 README 中还附有"与设计文档的差异（真实说明）"，是诚实交付的好范例。

### M4　核心技术（一）：任务编排、工具调用、护栏（1 学时）

**学习目标**：理解三项技术的设计要点，并能读懂对应代码结构。

| 时间 | 内容 | 要点 |
|---|---|---|
| 20 min | 4.1 任务编排 | 意图识别 → 子任务拆解 → 按意图选择工具链。TCMRxAgent 的规划器：规则规划（默认）+ LLM 规划（**只允许白名单工具**，失败回退规则）；不同意图对应不同工具链（求方 / 解释 / 比较 / 加减 / 药物 / 禁忌 / 出处）。WindOnMAgent 的"总控智能体 + 7 个专业智能体"，**总控无任何业务工具**，只负责调度 |
| 20 min | 4.2 工具调用 | 工具四要素：名称、描述、参数 Schema、返回格式；注册表式工具（统一耗时、错误处理、轨迹记录）；WindOnMAgent 的工具注册中心：Schema 校验、最小权限、配额、熔断、审计；**读写分离**（只读工具 vs. 写操作工具）；**没有向 SCADA 写控制指令的工具**，高风险操作只给提示 |
| 20 min | 4.3 护栏 | 三道关：**输入护栏**（急症/自伤/提示注入/越权）→ **过程护栏**（用药安全、权限、风险分级）→ **输出护栏**（核验引用条号/方名、剥离不该出现的剂量、禁止绝对化承诺，不通过则回退模板）。WindOnMAgent：风险分级 L0–L4，L3 须作业票 + 双人审批，L4 低置信转人工；RBAC + ABAC；哈希链审计（不可篡改） |

**课堂讨论**：你的行业里，哪些动作"智能体绝对不能自己做"？列出红线清单。

### M5　核心技术（二）：专业知识库与 RAG（1 学时）

**学习目标**：理解 RAG 全链路，会设计行业知识库的数据管线与检索策略。

| 时间 | 内容 | 要点 |
|---|---|---|
| 15 min | 5.1 为什么行业智能体离不开知识库 | 大模型的幻觉、时效与专业性问题；专业知识三形态：**结构化**（表）、**向量化**（文本块，供 RAG）、**图结构**（知识图谱） |
| 20 min | 5.2 RAG 全链路 | 数据来源 → 解析 → 校正（如编码转码错字）→ 切块 → 嵌入 → 入库 → 检索 → 重排 → 引用生成。**混合检索**：稠密向量（pgvector / Milvus）+ 关键词稀疏检索（BM25）→ **RRF 融合** → 轻量重排（命中候选加分、原文优先）。WindOnMAgent 的 GraphRAG：只检索 `status=active` 的有效规程版本 |
| 10 min | 5.3 嵌入模型与选型 | 案例中默认用"哈希 n-gram"嵌入（零依赖但语义弱），生产建议换成 bge-m3 等语义嵌入，换模型后须同步维度并**重新摄取** |
| 10 min | 5.4 RAG 常见问题 | 语料噪声（OCR/转码）、切块过碎或过长、引用不实、权限过滤缺失、版本过期；对策：来源标注、输出核验、权限过滤、版本管理 |
| 5 min | 5.5 演示 | 在 TCMRxAgent 前端查看"检索证据"，对照原文条文 |

**关键结论**：RAG 的价值在于"**可引用、可追溯**"；回答里引用的内容必须能在检索证据中找到，否则输出护栏应拦截。

### M6　实操一：用 CodeBuddy 搭建"最小行业智能体"（1 学时）

**目标**：1 小时内跑通"输入 → 规划 → 工具调用 → RAG 检索 → 带引用输出"闭环。

| 时间 | 步骤 | 说明 |
|---|---|---|
| 10 min | 环境与选题 | 每组选一个行业小场景（如设备告警解释、制度问答、药品说明查询）；准备 5–10 篇示例文档；配置 CodeBuddy 与模型 API |
| 35 min | 分步让 CodeBuddy 生成 | ① 项目骨架与配置 ② 文档解析与切块、向量入库 ③ 检索工具（含关键词 + 向量） ④ 1–2 个业务工具 ⑤ 简单规划器（意图分类 → 选工具）⑥ 带引用的答案合成 ⑦ 命令行或简单页面 |
| 10 min | 加最小护栏 | 最大步数、输入拒答规则、输出必须带引用，无依据则回答"无法确认" |
| 5 min | 小结 | 每组展示一次问答，指出一个失败案例 |

**提示词模板（示例）**：
> 你是资深 Python 工程师。请为"〔行业场景〕"实现最小智能体：1）读取 `docs/` 下文档，切块并存入 〔向量库〕；2）提供 `search_docs(query)` 工具，返回片段与来源；3）规划器先判断意图，再决定是否调用工具；4）答案必须标注来源，检索不到依据时拒答；5）为每个模块写单元测试。先给出目录结构，我确认后再逐个实现。

**交付物**：可运行的最小原型 + 一页"遇到的问题与改进想法"。

## 四、Day 2：知识图谱与记忆、案例拆解、综合实战

### M7　核心技术（三）：知识图谱与记忆（1 学时）

**学习目标**：理解知识图谱与记忆的作用、设计方法，以及与 RAG 的协作方式。

| 时间 | 内容 | 要点 |
|---|---|---|
| 25 min | 7.1 知识图谱 | **何时需要**：关系推理、多跳查询、鉴别比较、反向召回、溯源。**设计步骤**：本体（实体类型 + 关系类型）→ 抽取 → 校验 → 入库 → 查询。TCMRxAgent：节点 Formula/Herb/Feature/Channel/Pathogenesis…，关系 `COMPOSED_OF`、`TREATS`、`DERIVED_FROM`、`CONTRASTS_WITH`、`CONTRAINDICATED_FOR` 等，用于方族来历、变方、鉴别、症状→方剂反向召回、子图可视化。WindOnMAgent：时态、版本、溯源、约束校验，部件更换保留履历、规程新版本使旧引用失效；用关系表 + 递归查询实现多跳 |
| 10 min | 7.2 LLM 抽取图谱的"五层校验" | Schema → 术语归一化 → 图谱约束 → 台账/工单交叉验证 → 专家审核；**LLM 输出不直接入图** |
| 15 min | 7.3 记忆 | 三层记忆：**工作记忆**（会话槽位：已确认/否认症状、焦点对象、已追问项）→ **逐轮记录**（脱敏）→ **长期记忆**（咨询摘要向量 + 用户画像）。作用：多轮追问不丢上下文；跨会话个性化。配套：PII 脱敏、用户可一键删除个人数据、会话与用户严格隔离 |
| 10 min | 7.4 RAG、知识图谱、记忆如何协作 | RAG 找"原文证据"，图谱做"关系推理与鉴别"，记忆保证"多轮连续"；三者结果汇入同一回答合成，并通过输出护栏核验 |

**课堂讨论**：你的行业最需要图谱回答哪类问题？画出 5 类实体、6 种关系的初版本体。

### M8　案例一：TCMRxAgent——中医方证学习智能体（1 学时）

**案例定位**：面向中医初学者的**辅助决策型**智能体（教学辅助而非诊疗系统）；用户描述症状、舌脉，系统给出《伤寒论》可能对应的方剂，并**说明开方原因**，支持继续追问。

| 时间 | 内容 | 要点 |
|---|---|---|
| 10 min | 8.1 需求与边界 | 功能：症状求方、开方理由、追问、方剂追问、多轮记忆、方剂百科（112 首方）、透明度、隐私；**边界**：不给现代克数剂量、不建议自行服药、急危重症拦截并引导就医 |
| 15 min | 8.2 架构拆解 | 三层：React 前端 → Node 后台（BFF：身份、会话持久化、限流、SSE 转发）→ Python 智能体（医学推理）；共用 PostgreSQL + pgvector，**各写各的表**；外部 LLM/联网检索可选，不可用时自动降级为本地模板 |
| 15 min | 8.3 一次问答的八个阶段 | 加载记忆 → 输入护栏 → 症状抽取 → 任务拆解 → 与记忆合并 → 辨证打分 → 图谱扩展 + RAG 混合检索 + 条文溯源 + 用药安全审查 →（可选联网参考）→ 回答合成 →（可选 LLM 润色）→ 输出护栏 → 保存记忆并写审计 |
| 10 min | 8.4 五大技术点对照 | **任务编排**：`planner.py` 意图路由；**工具**：`extract_symptoms / rank_formulas / kg_expand / retrieve / clauses / safety_review / herb_info`；**记忆**：工作 + 逐轮 + 长期；**护栏**：输入/用药安全/输出三道；**知识库**：398 条原文 + 112 方档案 + 8 部古籍（RAG）+ 知识图谱 |
| 5 min | 8.5 设计亮点 | **可解释打分**：得分 = Σ命中权重 + 近义部分分 + 脉舌加分 − 冲突/禁忌惩罚；**LLM 不参与打分**，结论可复现、可审计；信息不足时生成"能区分候选方的追问"；联网结果只作参考证据，不带个人信息 |
| 5 min | 8.6 局限与反思（重要） | 知识画像**未经中医师审校**；18/18 的评测只是回归基线，**不能当作真实准确率**；默认嵌入语义弱；症状抽取基于词表；Docker 配置未经验证 |

**现场演示**：命令行 `python -m tcmagent.cli "发热恶寒，无汗而喘，头痛身痛，脉浮紧" --trace`，观看执行轨迹；再演示急症拦截与追问。
**课堂任务**：对照本案例，写出你所在行业的"可解释打分/规则"应由谁来维护、谁来审校。

### M9　案例二：WindOnMAgent——海上风电运维智能体（1 学时）

**案例定位**：**半自主型 + 多智能体协作**的运维智能体，覆盖诊断、预警、工单、闭环执行；技术思路为"**知识图谱（可信底座）+ 大模型（理解与生成）+ 总控/专业多智能体（规划、工具调用、闭环）**"，数据库为 PostgreSQL。

| 时间 | 内容 | 要点 |
|---|---|---|
| 10 min | 9.1 场景与需求 | 风场运维：故障诊断、能效分析、资源调度、工单管理、知识沉淀、持续改进；多角色（值班运维、检修工程师、审批人、知识管理员、领域专家、管理员） |
| 15 min | 9.2 架构拆解 | 总控智能体 + 7 个专业智能体（六层内部结构）；工具注册中心（MCP 风格）；服务层（图谱 / 文档检索 / 时序 / 规则 / 诊断 / 能效 / 资源 / 工单 / 知识工程 / 改进 / 报表）；边缘节点（72h 缓存、断链续传、校验和幂等）；FastAPI（REST + SSE + WebSocket） |
| 15 min | 9.3 五大技术点对照 | **编排**：状态机 + Checkpoint + 人工审批（`WaitingApproval`，支持暂停/终止/恢复/回滚）；**工具**：白名单、Schema 校验、最小权限、配额、熔断；**记忆与状态**：任务状态与检查点持久化；**护栏**：风险分级 L0–L4、双人签批、RBAC+ABAC 风场隔离、WORM 哈希链审计；**知识库**：时态知识图谱 + GraphRAG 混合检索（向量 + BM25 → RRF → 重排） |
| 10 min | 9.4 知识工程与持续改进闭环 | LLM 抽取 + 五层校验；反馈收集 → 根因分析 → 参数校准 → **黄金集门禁（≥85%）** → 灰度/全量，周期 ≤30 天 |
| 10 min | 9.5 现场演示 | 按 DEMO.md 的分角色流程：值班运维提问诊断 → 触发预警与紧急工单 → 检修工程师执行 → 审批人双签 → 审计校验 |
| 5 min | 9.6 工程取舍（诚实说明） | 设计文档选型的 Neo4j / Milvus / TDengine / Kafka / LangGraph / Temporal 等，在实现中用 **PostgreSQL 与自研等价最小实现**替代，接口已隔离、可平滑替换；该项目**未使用智能体框架**；真实 SCADA/EAM 由仿真器与种子数据提供 |

**对比小结表（课堂填写）**：

| 维度 | TCMRxAgent | WindOnMAgent |
|---|---|---|
| 自主程度 | 辅助决策型 | 半自主 + 多智能体 |
| 核心风险 | 医疗误导 | 设备安全与生产事故 |
| 编排方式 | 规则规划为主，LLM 规划可选 | 总控 + 专业智能体、状态机 |
| 知识库 | RAG + 静态图谱（古籍/条文） | GraphRAG + 时态图谱（规程/台账/故障因果） |
| 记忆 | 会话 + 长期画像 | 任务状态 + 检查点 |
| 护栏重点 | 急症拦截、用药安全、输出核验 | 风险分级、双人审批、权限隔离、审计 |
| 人在回路 | 追问与免责声明 | 审批、作业票、低置信转人工 |

### M10　其他类型智能体案例巡礼；评测、治理与上线（1 学时）

**学习目标**：扩大视野，认识不同类型智能体的技术差异，并掌握上线前的质量与治理要求。

| 时间 | 内容 | 要点 |
|---|---|---|
| 30 min | 10.1 各类智能体开发案例巡礼 | 按自主程度举例，每类讲"场景 → 推荐技术 → 风险边界"。<br>**被动响应型**：能源知识问答、设备数据查询、告警解释（RAG + SQL 智能体 + 权限过滤）<br>**辅助决策型**：PHM 故障诊断 Copilot、预测性维护方案、PEM/PQM 分析（时序模型 + 知识图谱 + 人工确认）<br>**任务执行型**：PHM 工单、日报月报生成、质量异常闭环（工作流 + 审批 + 审计）<br>**半自主型**：风电场/光伏健康监控、储能安全与寿命管理、检修资源协同<br>**全自主型**：仅限仿真沙箱与低风险可回滚系统（数字孪生）<br>**多智能体协作**：PHM 多智能体、电力交易与综合能源运营分析（Supervisor + 合规审核智能体）<br>**通用应用**：客服机器人、代码助手、多智能体协作系统的数据库设计与技术选型（向量规模、消息队列、工作流引擎、多租户隔离、事务一致性） |
| 10 min | 10.2 评测 | 评测集必须**独立于开发者**（避免"自己出题自己答"）；覆盖带噪声、口语化、边界与攻击用例；指标：任务完成率、工具调用成功率、引用准确率、人工介入率、响应时长、Token 费用；回归基线 ≠ 真实准确率 |
| 10 min | 10.3 治理、部署与上线 | 身份认证与权限、数据分级与脱敏、提示注入防护、全链路审计、版本与回滚、应急停止；密钥管理（`config.env` 不入库）；生产环境必须修改默认密钥与演示账号；**降级方案**（外部模型不可用时回退本地模板）；专家审校后再面向真实用户 |
| 10 min | 10.4 常见失败模式清单 | 死循环、工具乱调、幻觉引用、越权、知识过期、上下文丢失、成本失控；对应的边界设置与监控指标 |

## 七、讲师提示与风险说明

1. **术语统一**：智能体 = LLM + 记忆 + 工具 + 规划 + 反馈循环；多智能体协作是组织方式而非自主等级。
2. **诚实对待案例**：TCMRxAgent 的知识画像未经专家审校，评测数字只是回归基线；WindOnMAgent 以 PostgreSQL 和自研实现替代了设计文档的多种基础设施。授课时应明确这些局限，引导学员建立"不夸大、可核验"的交付习惯。
3. **框架版本变化快**：授课前核对 LangGraph、MCP、A2A 等最新版本与写法；AutoGen 已归档，不作为新项目推荐。
4. **高风险行业红线**：医疗、能源控制、金融等场景，一律保持"智能体辅助 + 规则约束 + 人工确认"，演示中不得展示可直接作用于真实生产系统的控制动作。
5. **时间弹性**：若进度紧张，M10 的案例巡礼可压缩为"自学材料"，把时间让给 M11 实操；若学员基础较弱，M6 可由讲师提供骨架代码，学员在其上补全。
