RAG 检索增强生成原理详解
====================

一、RAG 是什么
RAG（Retrieval-Augmented Generation，检索增强生成）= 先检索、后生成。让大模型在回答前先从知识库中查找相关资料，把检索到的内容作为上下文喂给模型，从而：
- 缓解幻觉：回答有据可依，可附引用来源
- 突破知识时效：知识库可随时更新，无需重训模型
- 保护私有数据：企业内部文档留在向量库，不进入模型参数

二、RAG 完整流程（离线索引 + 在线检索生成）

【离线：索引流水线】
1. 文档加载：从 PDF/Word/网页/数据库等来源解析出纯文本
2. 文档切块（Chunking）：
   - 固定长度切块：简单但可能切断语义
   - 语义切块：按句子/段落边界与主题变化切分
   - 父子块（Small-to-Big）：用小块做检索匹配，返回大块给模型
   - 经验值：单块 200~800 token，块间保留 10%~20% 重叠
3. 向量化（Embedding）：用嵌入模型（如 DeepSeek/OpenAI embedding、BGE、m3e）把文本块映射为高维向量，语义相近的文本向量距离更近
4. 入库：向量 + 原文 + 元数据（来源、时间、权限）写入向量数据库（FAISS、Milvus、Chroma、Qdrant、pgvector）

【在线：检索生成流水线】
1. 查询预处理：改写（同义扩展）、HyDE（先生成假设答案再检索）、多路查询分解
2. 检索（Retrieval）：
   - 稠密检索：查询向量化后做最近邻搜索（ANN），擅长语义匹配
   - 稀疏检索：BM25/关键词，擅长精确术语、编号、人名匹配
   - 混合检索（Hybrid）：稠密 + 稀疏并行检索再融合（RRF 倒数排名融合），效果通常最好
3. 重排序（Rerank）：用 Cross-Encoder 精排模型（如 BGE-reranker、Cohere Rerank）对初筛的 top-50 精排出 top-5
4. 上下文组装：把重排后的证据块按相关度拼入提示词，附来源元数据
5. 生成（Generation）：模型基于证据作答，提示词中明确要求"仅基于提供的证据回答，无法回答时明确说明"
6. 引用标注：把回答中的论断映射回证据来源，输出可审计的引用

三、向量检索的数学原理
- 余弦相似度：sim(q,d) = q·d / (|q||d|)，衡量两个向量方向的一致性
- 近似最近邻（ANN）：HNSW（分层可导航小世界图）、IVF（倒排文件索引）等算法，用少量精度损失换取海量向量的毫秒级检索
- 嵌入模型的训练目标：让"问题-正确答案"对的向量距离近，无关文本距离远（对比学习）

四、进阶模式
- GraphRAG：抽取实体关系构建知识图谱，检索时沿图扩展，适合多跳推理（"A 的合作方的竞争对手是谁"）
- Agentic RAG：让 Agent 自主决定检索几次、改写查询、评估证据是否充分，不够再检索
- 自适应 RAG：按问题复杂度路由——简单问题直接回答，复杂问题走完整检索链路
- 多模态 RAG：对图表、截图做视觉嵌入，图文混合检索

五、评估指标
- 检索质量：Recall@K（前 K 条是否命中相关文档）、MRR（正确答案排名）
- 生成质量：忠实度（回答是否忠于证据）、答案相关性、引用准确率
- 常用工具：RAGAS、TruLens

六、常见问题与对策
- 检索不到（召回低）→ 换更强的嵌入模型、混合检索、优化切块
- 检索到了但用不好 → 重排序、压缩上下文、改进提示词
- 知识更新滞后 → 增量索引、文档变更检测（增量更新而非全量重建）
- 多用户数据隔离 → 按租户/权限过滤元数据（检索时带权限条件）
