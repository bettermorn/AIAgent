AI Agent 的安全、权限与人工确认
====================

一、为什么安全设计必不可少
AI Agent 与普通聊天机器人的本质区别在于：Agent 能调用工具、执行代码、读写文件、访问外部 API。一旦被恶意利用（提示注入、越权操作、数据泄露），后果从"说错话"升级为"做错事"。因此安全层必须与能力层同步设计，而不是事后补丁。

二、输入安全
- 提示注入防御（Prompt Injection）：
  - 将用户输入与系统指令严格分离（分隔符、结构化字段）
  - 检索到的文档内容同样视为不可信输入（间接注入）
  - 对输入做敏感词与攻击模式检测，命中则拦截或降级
- 数据脱敏：身份证号、手机号、密钥等在进入模型前脱敏

三、输出安全
- 幻觉控制：要求模型基于检索证据作答并附引用，无法引用时明确说不知道
- 内容过滤：有害、违法、歧视性内容拦截
- 结构校验：工具调用参数做 Schema 校验，防止畸形参数破坏下游系统
- 防泄露：过滤输出中意外带出的系统提示词、内部配置、他人数据

四、工具与执行安全
- 最小权限原则：每个工具只授予完成任务所需的最小权限
- 沙箱执行：代码在隔离容器/进程中运行，限制文件系统、网络与 CPU/内存/超时
- 操作白名单：如数学求值仅允许 math.* 函数，禁用 eval/exec 裸调用
- 幂等与限流：写操作设计幂等键，防止重复执行造成重复扣款/重复发消息
- 资源限额：单次会话最大工具调用次数、最大 Token 消耗预算

五、权限分级（Permission Levels）
典型的权限分级模型：
- L0 只读（read-only）：仅可检索与生成文本，无副作用
- L1 低风险写（low-risk writes）：可写入用户私有空间（如保存笔记）
- L2 中风险（medium-risk）：可调用外部只读 API（搜索、查询数据库）
- L3 高风险（high-risk）：资金操作、发送邮件、删除数据、执行任意代码
不同用户/租户可被授予不同上限（safety_tier），Agent 的操作不得超过其所属等级。

六、人工确认（Human-in-the-loop, HITL）
核心思想：高风险动作在执行前暂停，等待人工批准。
- 触发条件：操作权限等级 >= 阈值、涉及金额、批量影响、低置信度判断
- 实现机制：
  - 编排框架的中断点（如 LangGraph interrupt）：暂停图执行，保存状态，等待人工输入后恢复
  - 审批工单流：高风险操作生成待审批任务，支持批准/驳回/修改参数
- 超时策略：长时间未审批自动取消并通知用户，避免任务悬挂
- 审批留痕：谁批准、何时、基于什么信息，全部入审计日志

七、审计与可观测
- 轨迹日志（Trace）：记录每个节点的输入、输出、工具调用与安全标记
- 完整审计链：用户请求 → 意图 → 计划 → 每步执行 → 最终输出，可端到端回溯
- 告警：异常频率、敏感操作、预算超限时实时告警

八、最佳实践清单
1. 默认拒绝（deny by default），白名单放行
2. 高风险操作必须人工确认，且确认信息要展示关键参数而非仅展示描述
3. 把检索内容、工具返回结果都当作不可信输入处理
4. 每次版本发布前跑对抗测试（注入、越权、诱导绕过）
5. 保留完整轨迹与审计日志，出问题能定位到具体节点
