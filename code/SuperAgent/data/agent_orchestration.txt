AI Agent 编排框架介绍
====================

一、为什么需要编排框架
单个大模型调用无法完成复杂任务。编排框架负责把"规划、检索、工具调用、生成、审查"等环节组织成可执行、可观测、可回溯的流程（DAG 或图结构），是构建可靠 Agent 系统的核心。

二、主流编排框架
1. LangGraph
   - LangChain 生态的图编排引擎，以有向图（StateGraph）组织节点
   - 节点接收共享状态（State），处理后返回状态更新
   - 支持条件边、循环、检查点（Checkpoint）与人工介入（Human-in-the-loop）
   - 典型模式：Planner → Researcher → Writer → Reflector
   - 适合需要精细控制流程与状态的生产级多智能体系统

2. AutoGen（微软）
   - 以"对话"为核心的多智能体框架，Agent 之间通过消息协商
   - 内置 GroupChat 管理多 Agent 讨论，支持人工介入节点
   - 适合研究型、探讨型任务（如多角色协作写作、代码评审）

3. CrewAI
   - 以"团队与角色"为抽象：每个 Agent 有角色、目标与背景故事
   - 通过 Task 分配与 Process（顺序/层级）驱动协作
   - 上手快，适合快速搭建角色分工明确的多 Agent 演示

4. OpenAI Agents SDK / Swarm 模式
   - 轻量 Handoff（移交）机制：Agent 之间互相转交控制权
   - 适合客服分流、简单路由类场景

5. 自研编排
   - 直接用状态机、消息队列或工作流引擎（如 Temporal）实现
   - 灵活性最高，但需要自行解决状态持久化、重试与可观测性

三、编排核心概念
- 状态（State）：全局共享的数据结构，节点读写并返回增量更新
- 节点（Node）：一个处理步骤，可以是 LLM 调用、工具执行或纯函数
- 边（Edge）与条件边：定义流转方向，支持分支与循环
- 检查点（Checkpoint）：持久化中间状态，支持故障恢复与时间旅行调试
- 人工介入（HITL）：在关键节点暂停，等待人工确认后继续

四、选型建议
- 需要严格控制流程、可回溯审计：LangGraph
- 需要多角色自由讨论：AutoGen
- 需要快速原型、角色清晰：CrewAI
- 简单路由场景：Handoff 模式即可，无需重框架
