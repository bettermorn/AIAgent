# 二、3 条安全规则（覆盖数据、权限、注入风险）
规则ID	安全规则	说明
SR-01	最小权限访问	Agent 仅能读取当前用户有权限查看的会议纪要（基于RBAC）。不得跨项目/跨部门访问纪要内容。输出任务列表时，仅向该会议参会人及纪要创建者展示完整信息，其他人（如组织外）需脱敏（负责人姓名部分隐藏，截止日期模糊）。
SR-02	输出内容防注入与敏感信息脱敏	对提取出的任务描述、负责人姓名、日期等字段进行 XSS/命令注入过滤（尤其当输出到Web或邮件时）。同时，若纪要中包含电话号码、邮箱、服务器IP、密码等敏感模式（正则匹配），在结构化输出中自动替换为 [REDACTED]，并记录告警日志。
SR-03	人工确认环节的身份强制校验	人工确认接口必须校验操作者身份（OAuth2/JWT），且仅允许 会议创建者、项目经理或被指派的负责人本人 确认/修改任务。每次确认操作需记录操作日志（谁、何时、确认了什么），不可篡改。禁止以明文传递任务ID或负责人ID（使用短时效签名令牌）。
# 三、1 个异常处理方案（针对解析失败 / 服务降级）
异常场景：

NLP 解析引擎超时（>5s）、返回空结果、或置信度低于阈值（<0.6）。

第三方日历/日期解析服务不可用。

处理方案（降级 + 人工兜底）：

降级策略：

若解析失败，立即回退到 正则表达式 + 规则模板（如匹配“@某人”、“截止/DDL”、“待办/需/必须”等关键词），提取粗粒度信息。

日期解析失败时，保留原始文本中的日期描述，不强制转换为标准格式，并在缺失字段中标记“日期解析失败”。

异步重试：

将原始纪要放入重试队列，指数退避重试最多3次（间隔1s, 2s, 4s）。若仍失败，则进入人工兜底。

人工兜底：

生成一个“低置信度任务草稿”并推送至指定负责人（如会议发起人），附带原始纪要片段，提示“自动提取未完成，请手动补充或确认”。

系统记录失败日志，用于后续模型迭代。

最终输出：

无论解析成功与否，保证输出结构完整（字段均存在，但可能为空或填充[待人工确认]），不影响后续流程（如任务列表生成）。

监控告警：若连续5分钟解析失败率 > 20%，触发运维告警。
